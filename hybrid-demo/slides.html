没有一种方法两边都赢——escalate 简单 −88% ↔ 困难 +71%（同一套代码！），context-engine 反之。 只有按难度分诊的路由 Agent 能吃满两列。红格是裸跑成本（坏 harness 的产物，见下页）；一次性判分保守实测，真实工作流可免费迭代、困难列更省。

没有好的 Agent harness，端云协同反而更贵

坏 harness · 裸跑实测

  • +71% 脏交接：失败笔记+半成品 diff 硬塞给云端消化、被错误锚定
  • +33% 协调循环：云端拆任务/审集成的开销 > 样板节省
  • +12% 坏上下文包：弱本地的错误定位误导云端（解题率也掉）
  • +59% 多余审查：任务可自证还让云端逐一复核（审查≈重做）

好 harness 的四件事

  • 按难度路由：简单→escalate；困难→context-engine；本地够强→先试自证
  • 裁判自证：跑测试当客观裁判，通过才敢交付（$0）
  • 干净交接：失败就丢弃半成品；强本地只递压缩包
  • 免费迭代：修→验→再修烧时间不烧 token，失败不是终局

Harness 本身是核心资产、也是最值得深挖的方向：路由信号实测（事前读题面 +10% ❌ · 事中先试卡住才升级 −41% ✅ · oracle −35% 仍有空间）。
