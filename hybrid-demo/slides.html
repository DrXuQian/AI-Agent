统一原理：把「不需要顶级智能、却烧 token」的活搬到免费本地 · 常见疑问

"云端不也看不到判分测试吗？"
对——「可验证」指任务自带裁判，不是谁能判卷

有裁判 · 可验证任务

J 写解▶跑测试 = 客观裁判▶✓ 敢停 · 云端 $0

跑测试不需要智商，弱模型也能当庭举证。实测：双卡自证 31/31 零假阳性；弱单卡 2/30 漏（自写测试越全越可靠）。

没裁判 · 不可验证任务

J："我觉得修好了"=意见 · 假阳性风险▶S 拍板 = 质量基准

判断力成了唯一质量来源，云端亲自做 = 基准（baseline）。复查也不便宜：无测试时审查 ≈ 重做（local-first 实测 −2.5%）。 难任务里自带裁判的子集（可复现 / 有现成测试）照样走左边——四卡实测 3/11 自解、零假阳性。

可验证性决定的是免费阶段敢不敢停：有裁判 → 整题外包给免费本地（escalate 双卡实测 −88%）； 没裁判 → 只外包探索体力活、云端拍板（context-engine 双卡实测 −23%）——本地当"免费的眼睛和手"，云端当大脑。 给任务装裁判（TDD / 先写测试）= 把负载搬进左边 = 最强省钱杠杆。
再进一步：真实 bug 自带症状复现、可免费迭代（修→验→再修，烧时间不烧 token，错了还有外层反馈兜底） → 两端都趋向可本地验证，真正的轴是迭代时间 × 验证完备度；一次性隐藏判分实测因此是下限。

包月订阅 · 个人 Pro/Max 类

降档 Max $200 → Pro $20减座位 10 → 3不撞限额

账单不自动变少——但订阅本质是限额：省 token = 同档干 5–20 倍的活。 兑现打折但不归零：货币从 $/token 变成"档位 × 座位数"。

进阶产品：与云厂商联合推「端云协同版 coding plan」——机器当入场券、云端只接升级题， 订阅价可以低一档（云厂商也乐意：获客 + 算力减压）；或机器捆绑云 credits 一体化订阅。
诚实的风险：token 补贴期省下的美元缩水。对冲：①涨价期权 ②主攻 API 客户 ③隐私腿——context-engine 天然"仓库不上云、只上压缩包"，省 token 的机制 = 缩小数据暴露面的机制。
