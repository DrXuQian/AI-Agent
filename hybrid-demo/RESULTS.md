# 云端编排 + 端侧小模型混合 Agentic Coding：省钱上限实验

**架构**：Claude Fable 5 做云端编排者（规划/接口设计/验证），Claude Sonnet 4.6 模拟端侧小模型
（worker），通过 `delegate_to_local` 工具委派子任务。每个版本同时跑混合臂和
`--no-delegate` 基线臂（纯 Fable，同任务同工具），保证公平对比。

**任务**（v2 起固定不变）：实现 `calclang` 表达式语言解释器 —— tokenizer / parser
（递归下降、优先级、右结合 `^`）/ evaluator（变量环境、内建函数）/ REPL，外加三个
pytest 测试文件，验收标准为全部测试通过。模块间有真实依赖链，逼迫编排者先定接口再委派。

## 迭代结果总表

| 版本 | 配置 | 基线云端成本 | 混合云端成本 | **云端节省** | 混合总成本(含worker) | 测试(基线/混合) |
|---|---|---|---|---|---|---|
| v2 | 无缓存，worker直写文件 | $0.5731 | $0.6400 | **−12%** ❌ | $0.7515 | 40 / 74 ✅ |
| v3 | +prompt caching +任务上下文带外共享 | $0.4077 | $0.3464 | **+15%** ✅ | $0.4996 | 28 / 119 ✅ |
| v4 | +effort=medium +首轮全量委派 +报告限8行 | $0.3452 | $0.2541 | **+26%** ✅ 峰值 | $0.3844 | 19 / 100 ✅ |
| v5 | effort=low +极限压缩（上限探测） | $0.2798 | $0.3136 | **−12%** ❌ | $0.4760 | 16 / 109 ✅ |

"云端节省"以同版本基线为参照。端侧 worker 边际成本≈0（真实 AI station 场景），
故云端开销是核心指标；若 worker 按 Sonnet API 价付费，则所有版本混合总成本均高于基线。

## 结论：本任务形态下省钱上限 ≈ 26%（实测峰值，v4 配置）

### 每一轮学到了什么

- **v1→v2（教训：别让代码流经编排者）**：v1 中编排者把 worker 产出重抄进自己的回复，
  输出 token 被白白翻倍。v2 改为 worker 直写文件、编排者只收 5 行摘要。
- **v2（教训：描述开销会吃掉全部节省）**：代码 100% 下放后混合臂反而贵 31% ——
  编排者省下的"写代码"token 全部花在了"给 worker 写规格说明"上（输出仅降 11%），
  且多轮往返使全价输入暴涨 60%。
- **v3（两个最大正向杠杆）**：
  1. **Prompt caching**：多轮历史按 0.1× 计费，混合臂（轮次多）获益大于基线；
  2. **任务上下文带外共享**：harness 自动把用户原始任务全文塞进 worker 的 system prompt
     （本地模型读本地上下文免费），编排者只发送接口决策增量。规格描述开销基本消失，
     混合首次反超基线。
- **v4（最优点）**：effort=medium 压掉过度 thinking；强制首轮并行委派全部 7 个文件，
  把编排轮次压到下限；报告限 8 行。云端节省达到 26%。
- **v5（撞到天花板的机制）**：把 effort 压到 low 后，编排者**协调质量本身退化**——
  无视"首轮全量委派"指令，改为 9 轮逐个委派（连一行的 `__init__.py` 都单独发一轮），
  轮次膨胀让缓存读取量从 18.7K 涨到 47.5K，节省全部回吐。
  **编排智力是混合方案的发动机，不能为省 token 而砍。**

### 为什么 26% 接近结构性上限

v4 混合臂的云端成本构成：输出 token $0.16（63%，= thinking + 委派消息 + 验证决策 + 报告）、
缓存写 $0.075、缓存读 $0.019。其中可继续压缩的只有委派消息的措辞冗余；
而**规划、接口设计、验证判读、收尾报告是编排者不可下放的本职工作**，
v5 证明用降智力换压缩会适得其反。对此类"一次规划、并行实现、一轮验证"的任务形态，
理论上限估计在 30–40%，实操稳定可得 ~25%。

### 上限的适用边界（外推到真实系统时的修正方向）

- **↑ 有利**：更大的代码产出量（代码 token 占比越高，下放收益越大）；更长的会话
  （缓存摊薄固定开销）；worker 能直接跑测试并自修复（验证轮次也下放）。
- **↓ 不利**：worker 返工（本实验 0 返工是上界条件——所有 worker 产出一次通过）；
  需要跨模块调试的任务（编排者必须读代码，输入成本回升）；任务规格本身模糊
  （接口决策的沟通成本上升）。

### 质量红利（意外收获）

所有混合臂的测试产出量都是基线的 3–6 倍（如 v4：100 vs 19），且全部通过。
即按"每单位工作量的云端成本"计，混合方案的实际优势远大于 26%。
原因：worker 写测试不占编排者预算，编排者乐于多委派。

## 复现

```bash
pip install anthropic pytest
python3 hybrid_demo_v4.py                # 最优配置混合臂
python3 hybrid_demo_v4.py --no-delegate  # 对应基线
```

认证：脚本自动使用 `CLAUDE_SESSION_INGRESS_TOKEN_FILE`（Claude Code 远程环境）
或 `ANTHROPIC_API_KEY`。每次运行约 $0.25–0.75。
