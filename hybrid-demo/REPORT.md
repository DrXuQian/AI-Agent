# 端云协同 AI Station：省 Token 实验报告与盈利分析

> 一句话结论：端侧免费算力 + 云端前沿模型，按任务形态可省 **23%–88% 的云端
> token 成本且不掉解题率**。按真实售价（单卡 ¥15k / 双卡 ¥24k / 四卡 ¥54k），
> **单卡 ¥15k 是走量主力**——月云端消耗 ≥$300 即 <2 年回本，个人也成立；
> 四卡 ¥54k 是团队/CI 设备。本文给出实测数据 + 三档可套用的盈利测算。

---

## 0. 实验设置（核算口径）

- **硬件假设**：端侧本地模型算力**免费**（自有 AI station，电费忽略）；只计**云端
  API token 成本**。这是 AI station 的核心商业前提。
- **云端模型**：Claude Opus 4.8（\$5 / \$25 per Mtok 输入/输出）。
- **本地模型**：实验用 Claude **Haiku 4.5**（SWE-bench Verified **73.3%**）/ Sonnet 4.6
  扮演端侧模型。**关键**：Haiku 4.5 与单卡档真实端侧模型 **Qwen3.5-122B-A10B
  （~72%）几乎同分**——所以实测省钱率直接适用于单卡档，不再只是代理估计（见 §0.1）。
- **判分**：代码任务用**官方隐藏测试**判对错（SWE-bench 用 FAIL_TO_PASS +
  PASS_TO_PASS；HumanEval+ 用 EvalPlus 强化测试集），不是自评。
- **成本计量**：精确累计每次 API 调用的 input / cache write / cache read / output
  四类 token，按官方单价折算（cache write ×1.25，cache read ×0.1）。

### 0.1 硬件档位 × 端侧模型 × 省钱率（联网核实的真实模型 + 真实售价）

端侧模型能力（SWE-bench Verified）越接近云端 Opus 4.8（88.6%），可外包给本地的
工作越多 → 省钱率越高。三档真实硬件 / 真实开源模型 / 真实售价：

| 档位 | 售价(¥/≈$) | 端侧模型(int4) | 全精度→int4 Verified | 对省钱率的含义 |
|---|---|---|---|---|
| **单卡** | ¥15,000 / ~$2,083 | Qwen3.5-122B-A10B-int4 | 72% → **~68%** | ≈ 实验代理 Haiku 4.5（73.3%），略低 → **实测 −23%/−88% 基本适用**（int4 略打折） |
| **双卡** | ¥24,000 / ~$3,333 | Qwen3.5-397B-A17B-int4 | ~80% → **~76%** | 强于代理 → 省钱率 ≥ 实测 |
| **四卡** | ¥54,000 / ~$7,500 | GLM-5.2-int4 / MiniMax-M2.7-int4 | ~81% → **~77%** | 逼近 Opus → 本地自解率更高，escalate 收益更大 |

> 参照：云端 Opus 4.8 = 88.6%，Sonnet 4.6 = 79.6%，Haiku 4.5 = 73.3%。汇率 7.2。
> **int4 掉分**：量化相对全精度约掉 3–4 分（估计，待官方 int4 榜确认）。单卡 int4
> (~68%) 略低于实验代理 Haiku(73.3%)，故单卡的 escalate 自解率会略降、省钱略打折；
> 但 context-engine 只要求"会读代码"，对这 5 分差不敏感，−23% 方向稳健。
> **核心推论**：更大档位 = 更强模型 = 更高可外包比例 = 更高省钱率（单调）。

## 1. 测试方法

我们在**两个公开标准基准**上，对比"纯云端 baseline"与多种端云协同架构的云端成本。
两个基准都用**第三方隐藏测试客观判分**（agent 看不到、改不了），且卡住了"本地
可验证性"这根关键轴的两端——这正是决定省多少 token 的核心变量。

### 1.1 两个公开基准（按"本地可验证性"两端取点）

| 基准 | 任务形态 | 本地能否自证正确 | 成本大头 |
|---|---|---|---|
| **SWE-bench Lite** | 真实 GitHub issue bug 修复 | 弱（看不到判分测试） | 代码探索/诊断 |
| **HumanEval+** | 给签名+docstring 写函数 | 强（自带测试可跑） | 求解本身 |

> 为什么是这两个：核心结论是"**省多少取决于任务形态（可验证性）**"，证明它必须
> 跨越这根轴的不同点。SWE-bench（弱自证/探索密集）与 HumanEval+（强自证/纯生成）
> 卡住两端，足以确立全部结论。两者均为学术界公开基准、隐藏测试判分，是硬证据。

### 1.2 测试的五种端云架构

1. **baseline**：纯云端，自己探索+修复（对照组）。
2. **hybrid**：云端编排，把规格化的子任务委派给免费本地（云端少写）。
3. **local-first**：本地先完整做完，云端只审查/救场。
4. **escalate**：本地先做并自评，**只在自评失败时**升级云端。
5. **context-engine**：本地做免费探索/读代码，产出压缩上下文包；
   **云端只推理决策、不探索**（云端少读）。← 难任务上的赢家

每个实例独立 venv、克隆到 bug 引入的 commit；agent 改完后应用官方测试判分，
判分前清除 agent 对测试目录的任何改动（防作弊）。

### 1.3 SWE-bench 如何判分（为什么是硬证据）

判分用**维护者当年修 bug 时一起提交的官方测试**——agent 全程看不到、改不了。

1. **起点**：仓库 checkout 到 bug 引入的 commit（坏状态），agent 在此基础上改代码。
2. **叠加官方测试**：agent 改完后，判分器把官方 `test_patch`（只含测试、不含修复）
   打上去。这些测试 agent 接触不到。
3. **跑两组测试**：
   - **FAIL_TO_PASS（F2P）**：修复前必失败、修复后必须通过 → 验证"bug 真修好了"。
   - **PASS_TO_PASS（P2P）**：修复前后都应通过 → 验证"没改坏别的"（无回归）。
4. **判定**：**F2P 全过 且 P2P 全过 = RESOLVED（得分）**，否则不得分。二元判定，无部分分。

防作弊/严谨措施：叠加官方测试前清除 agent 对测试目录的改动；P2P 取"修复前确实
能通过"的样本做基线。**对错由第三方隐藏测试客观判定**——这是 SWE-bench 结论可信
的根本。HumanEval+ 同理（用 EvalPlus 强化隐藏测试集判分）。

## 2. 不同难度的省 Token 结果（实测）

### 2.1 总览：每种任务形态的最优方法与省钱幅度

| 任务形态 | 最优架构 | 云端省钱 | 解题率 | 样本 |
|---|---|---|---|---|
| **可验证函数生成**（HumanEval+） | escalate | **−88%** | 31/31（=baseline） | 30 题 |
| **真实仓库 bug 修复**（SWE-bench） | context-engine | **−23%** | 7/11（=baseline） | 11 实例 |

### 2.2 HumanEval+（可验证生成）：escalate −88%

| 架构 | 解题率 | 云端成本 | vs baseline |
|---|---|---|---|
| baseline（纯 Opus） | 31/31 | \$0.1033 | — |
| **escalate** | **31/31** | **\$0.0119** | **−88%** |
| local-first | 30/31 | \$0.1641 | +59%（每题都审查反而更贵） |

- **29/31 题零云端成本**：本地写解+自测通过→不升级，云端一分钱不花。
- 质量无损：自测通过的题，隐藏 EvalPlus 测试也通过——本地自验证可信。

### 2.3 SWE-bench（难任务/诊断密集）：只有 context-engine 为正

| 架构 | 解题率 | 云端成本 | vs baseline |
|---|---|---|---|
| baseline（纯 Opus） | 7/11 | \$3.049 | — |
| **context-engine** | **7/11** | **\$2.338** | **−23%** ✅ |
| hybrid | 10/11 | \$4.256 | +33% ❌ |
| escalate | 11/11 | \$5.49 | +71% ❌ |
| local-first | 8/11 | \$3.124 | −2.5% |
| **oracle（理论最优路由）** | 8/11 | \$1.988 | **−35%** |

- 难任务上**只有 context-engine 省钱且不掉质量**。其它方法要么更贵（hybrid/escalate
  陷入协调循环），要么掉解题率（local-first）。
- **机制验证**：context-engine 把云端**输入侧 −23%、输出侧 −24%**——本地接管探索后
  云端不再反复读代码，且拿到好上下文后推理更聚焦。本地免费承担了 \$3.15 探索量。
- **最难的一题 pylint-7114**：baseline 花 \$0.78 还**失败**；context-engine \$0.25
  **解出来了**——省钱同时提升质量。

### 2.4 为什么 escalate 在难任务上失败（关键教训）

同一套 escalate 代码：HumanEval+ −88%，SWE-bench +71%。唯一区别是**本地能否自证
正确**。SWE-bench 看不到判分测试，本地无法可信地报"已解决"→ 每题都升级 → 退化成
"本地白跑 + 云端从头做"。**省钱的前提是本地能闭环验证正确性。**

## 3. 省 Token 的统一原理

> **省 token = 把"不需要云端顶级智能、但消耗大量 token"的工作，搬到免费的本地。**

不同任务，这块"可外包工作"是不同的东西，所以最优架构随任务形态变：

| 任务形态 | 可外包给本地的大头 | 方法 | 实测省 |
|---|---|---|---|
| 可验证生成 | 整个求解（本地能自证） | escalate | −88% |
| 难 bug 修复 | 代码探索/定位（不需自证，只需会读码） | context-engine | −23% |

> 注：批量多文件生成（云端编排、委派样板代码给本地）的 hybrid 架构，在内部
> 自造任务上观察到约 −26%，但因属"自出题自判分"未列为硬证据；要补成公开硬证据，
> 下一步用 BigCodeBench（公开、调真实库、自带 unittest）。见 §6。

**context-engine 的独特价值**：它**不要求本地能自证正确**，只要求本地会读代码、会
grep——这是端侧小模型也能做好的，所以能用在 escalate 失败的难任务上。这正是
AI station 的核心能力：**本地当云端"免费的眼睛和手"，云端当大脑。**

## 4. 什么情况下盈利（三档真实售价，人民币）

> 售价：单卡 ¥15,000（~$2,083）/ 双卡 ¥24,000（~$3,333）/ 四卡 ¥54,000（~$7,500）。
> 汇率 7.2。云端 API 按 USD 计、本地算力免费，故只看"云端月省钱 vs 机器价"。

### 4.1 盈利公式

省钱率是**百分比**（对 token 绝对价格免疫），机器年价值随之线性放大：

```
年节省(USD) = 云端月消耗(USD) × 12 × 混合省钱率(%)
回本年数    = 机器售价(USD) / 年节省(USD)
```

混合省钱率取决于负载：难任务/bug 修复 ≈ **23%**；一般 ≈ **30%**；
偏可验证（TDD/测试生成/批量重构）**50%–88%**。

### 4.2 各档 2 年回本所需「云端月消耗」（盈亏平衡线）

| 档位 | 售价 | 省23% | 省30% | 省50% | 省88% |
|---|---|---|---|---|---|
| **单卡** | ¥15k | ≥$377/月 | ≥$289/月 | ≥$174/月 | ≥$99/月 |
| **双卡** | ¥24k | ≥$604/月 | ≥$463/月 | ≥$278/月 | ≥$158/月 |
| **四卡** | ¥54k | ≥$1,359/月 | ≥$1,042/月 | ≥$625/月 | ≥$355/月 |

### 4.3 回本年数（省钱率 30%，行=云端月消耗 / 列=档位）

| 月消耗 | 单卡 ¥15k | 双卡 ¥24k | 四卡 ¥54k |
|---|---|---|---|
| \$150  | 3.9 年 ⚠️ | 6.2 年 ❌ | 13.9 年 ❌ |
| \$300  | **1.9 年 ✅** | 3.1 年 ⚠️ | 6.9 年 ❌ |
| \$600  | **1.0 年 ✅** | **1.5 年 ✅** | 3.5 年 ⚠️ |
| \$1,000 | 0.6 年 ✅ | 0.9 年 ✅ | **2.1 年 ✅** |
| \$2,000 | 0.3 年 ✅ | 0.5 年 ✅ | 1.0 年 ✅ |

（✅ <2.5 年 / ⚠️ 2.5–4 年 / ❌ >4 年）

### 4.4 核心判断（真实售价大幅改善了经济性）

之前按 $8,000 假设时结论偏悲观；按真实人民币售价，**门槛低得多**：

- **单卡 ¥15k**：是**个人甜点**。月云端消耗 ≥$300（一个全职重度 Claude Code 用户
  很容易到）即 1.9 年回本；偏可验证负载只需 ≥$174/月。个人买得起、也回得了本。
- **双卡 ¥24k**：小团队 / 重度个人，月 ≥$600 即 1.5 年回本。
- **四卡 ¥54k**：**团队/CI 共享设备**，需月 ≥$1,000（团队级）才 2 年回本——不该卖给个人，
  天然是团队摊薄。但它的本地模型最强（~77%），省钱率上限也最高。

**关键转折**：硬件足够便宜后，"个人买省钱机器"在单卡档**第一次成立**了——这是
$8,000 假设下不成立的。单卡 ¥15k 应作为**走量的主力 SKU**。

### 4.5 两个放大器

1. **产品引导可验证负载**（省钱率 23%→50%+）：单卡盈亏线从 $377/月 降到 $174/月，
   几乎所有重度个人都覆盖。**最可控的抓手。**
2. **云端涨价对冲**：省钱率是百分比 → 机器价值随云端 token 单价线性放大。
   云端涨 2x，所有档位回本期减半。机器本质是"做空云端涨价"的对冲。

## 5. 商业建议（三档真实售价下）

1. **单卡 ¥15k = 走量主力，可直接按"省钱机器"卖给个人**——月云端 ≥$300 即 <2 年回本，
   这是真实售价带来的新结论（$8,000 假设下个人不成立）。
2. **四卡 ¥54k = 团队/CI 设备**，按"团队共享 + 1–2 年回本"ROI 话术卖，需月 ≥$1,000；
   不要卖给单个个人。
3. **隐私合规客户**（金融/医疗/政企）：任意档都卖"私有前沿 AI 盒子"——
   代码不出域 / 零 rate-limit / 离线是主卖点，token 省钱是叠加红利。
4. **产品主动把负载引导到可验证工作流**（TDD/测试生成/批量重构）——
   把省钱率从 23% 拉到 50%+，盈亏线砍半，是覆盖更多客户的唯一物理抓手。
5. **int4 掉分需实测确认**：单卡 int4 (~68%) 略低于实验代理，escalate 自解率会略降；
   context-engine（−23%）对此不敏感，可作为单卡档的稳健默认。

## 6. 局限与下一步

- **样本与方差**：SWE-bench 每实例单次运行，agent 成本方差 ±50%；−23% 是 11 题合计，
  方向稳健但精确值需每题 3 重复取均值。
- **本地模型代理**：用 Haiku 4.5（Verified 73.3%）扮演端侧模型，与单卡档真实模型
  Qwen3.5-122B-A10B（~72%）几乎同分——故单卡档省钱率已被实测覆盖，非估计；
  双卡/四卡模型更强，省钱率只会更高（见 §0.1）。
- **下一步**：
  1. **补 BigCodeBench**（公开、调真实库、自带 unittest）：把"批量多文件生成"这个
     任务形态也变成公开硬证据，替掉已弃用的自造 calclang。
  2. **in-flight 路由**：云端小预算内自探索，卡住才注入免费本地包（初步难子集 −41%，
     待调预算/成功检测）→ 逼近 oracle 的 −35%。
  3. **真实 vLLM 端点**：把 worker 换成本地实跑的端侧模型（单卡 Qwen3.5-122B /
     双卡 397B / 四卡 GLM-5.2），按档位得到产品级真实数字，替掉 Haiku 代理。
  4. **统计化**：全量 SWE-bench + 每题 3 重复，给出带置信区间的省钱率。
