# 地铁出行时间计算器（随申行数据）

根据随申行式的地铁线网数据，计算 **从 A 站到 B 站的整体出行时间**。综合考虑：

- 🚆 **区间运行时间**：每段相邻车站之间的乘车时间；
- 🔄 **换乘预留时间**：换乘站台间的步行时间（每个换乘点可单独配置）；
- ⏱️ **候车时间**：到站时**下一班车的到达/发车等待**——按时刻表精确计算，而不是拍脑袋；
- 🧮 把以上三部分（乘车 + 候车 + 换乘步行）加总成一个**全程时间**，并给出逐段行程。

纯 Python 标准库实现，无第三方依赖。

## 快速开始

```bash
cd metro-planner

# 1 号线莘庄 → 2 号线陆家嘴（早高峰 08:00，自动选最快路线、含换乘）

# 需要两次换乘的例子（晚高峰）
python -m metro.cli --from 莘庄 --to 四川北路 --depart 18:10

# 查看内置示例线网里有哪些线路与换乘站
python -m metro.cli --list
```

### 命令行参数

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `--from` | 起点站名 | — |
| `--to` | 终点站名 | — |
| `--depart` | 出发时刻 `HH:MM` | `08:00` |
| `--data` | 线网数据 JSON 路径 | 内置上海示例 |
| `--wait-model` | 候车模型：`grid` / `half` / `full` | `grid` |
| `--list` | 列出所有线路与换乘站 | — |
| `--json` | 以 JSON 输出（便于二次开发） | — |

### 候车模型 `--wait-model`

| 模型 | 含义 | 适用场景 |
| --- | --- | --- |
| `grid` | 由「首班车 + 发车间隔」生成**协调时刻表**，每站按距始发站的运行时间错相位，算出**精确的下一班车等待** | 默认，最贴近真实「下一班车到达」 |
| `half` | 候车 = 发车间隔 ÷ 2（期望等待） | 只有间隔、想要平均估计 |
| `full` | 候车 = 发车间隔（最坏情况） | 想要保守上限 |

## 算法

这是一个**时间相关的最早到达问题**（time-dependent earliest-arrival），用 Dijkstra 求解。

- **节点**：`(车站, 线路, 方向)` —— 表示「你在某站、乘某线、朝某方向」。另有虚拟起点/终点。
- **边与代价**：
  - *上车*（起点）：代价 = 等下一班车的时间；
  - *坐一站*：代价 = 区间运行时间，**不重复候车**（还在同一辆车上）；
  - *换乘*：代价 = 换乘步行（预留）+ 在新线路重新等下一班车；
  - *到站下车*：代价 = 0（可配出站时间）。

因为「坐车不重复候车、每次上车/换乘都按时钟计算真实等待」，所以**到达时刻最短的路径 = 真实最快的行程**。候车函数满足 FIFO（等得越久不可能到得越早），保证 Dijkstra 正确。

`grid` 时刻表生成方式：始发站按 `首班车, 首班车+间隔, …` 发车；任意中间站的到站/发车时刻 = 始发时刻 + 从始发站到该站的累计运行时间。由此「下一班车等待」是精确值，并且与「坐车不重复候车」完全自洽。

## 用真实随申行数据替换示例

内置 `data/shanghai_sample.json` 只含 1/2/8/10 号线的**部分车站**，时间为**示意值**，仅供演示。把它换成随申行导出的真实数据即可得到精确结果——数据格式如下：

```jsonc
{
  "meta": { "city": "上海", "source": "随申行" },

  "defaults": {
    "transfer_minutes": 4,            // 换乘默认步行时间（无单独配置时）
    "same_line_reverse_minutes": 3,   // 同线反向（坐过站折返）默认时间
    "egress_minutes": 0,              // 到达后出站时间
    "service": {                      // 各线缺省运营时刻（可被单条线路覆盖）
      "0": { "first": "05:30", "last": "23:00",
             "periods": [ {"from":"07:00","to":"09:00","headway":3}, … ] },
      "1": { … }
    }
  },

  "lines": [
    {
      "id": "1",
      "name": "1号线",
      "stations": ["莘庄", "上海南站", "徐家汇", …],   // 按 0→末 的顺序
      "segments": [3, 4, 2, …],                       // 长度 = 车站数 - 1，相邻区间运行分钟
      "service": { "0": {…}, "1": {…} }               // 可选，不填则用 defaults.service
    }
  ],

  "transfers": [
    { "station": "人民广场", "between": ["1","2"], "minutes": 4 },  // 该换乘点步行预留
    …
  ]
}
```

字段约定：

- **方向**：`0` = 沿 `stations` 列表正向（朝 `stations[-1]`），`1` = 反向（朝 `stations[0]`）。
- **`segments[j]`** = 第 `j` 与第 `j+1` 个车站之间的运行时间（默认双向相同）。
- **`service`** 用 `headway`（单一间隔）或 `periods`（分时段间隔，如平峰/高峰）二选一；用 `periods` 时按时间段查对应间隔。
- **`transfers`**：同一换乘站、给定两条（或多条）线路之间的步行预留时间；未配置的换乘点回退到 `defaults.transfer_minutes`。

> 从随申行/官方时刻表整理数据时，只要凑齐「线路站序、相邻区间运行时间、各线发车间隔（或时刻表）、换乘步行时间」四类信息即可。若你手头是**逐班车的真实时刻表**而非固定间隔，可把每站的实际发车时间直接生成为 `periods` 等价的网格，或扩展 `model.py` 的 `station_departures` 直接读时刻表。

## 已知简化（便于后续扩展）

- 环线（如 4 号线）按线性处理，暂不绕环；
- 区间运行时间默认双向相同；
- 不跨日（过末班车后报「不可达」，而非顺延到次日首班车）；
- 大小交路、越行/快车、同台换乘的细节未建模。

以上都可在 `model.py` 中按需扩展，核心规划算法无需改动。
